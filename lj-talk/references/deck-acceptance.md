# Deck acceptance

Use after creating or revising a PPTX. Run the available static plan checks and render the resulting
deck when a local renderer is available. For a new or substantially restructured classroom deck,
inspect the full learner route at the actual canvas. For a narrow edit, inspect affected pages and their
surrounding transitions. Check for overflow, collisions, unreadable type, contrast, hierarchy,
alignment, visible attribution, and the relation between a figure and its title. A typo-only edit does
not require an exhaustive visual review.

Confirm that native text and key scientific labels remain editable where the plan calls for them;
that supplied evidence is embedded as independent media; that display derivatives carry their recorded
provenance; and that notes do not expose private material. For video or live demonstrations, record a
playback path and an offline fallback still.

For scientific visuals, compare the displayed shape or arrangement, dimensions, data units, and labels
with the cited source as well as checking arithmetic or formulae. A numerically correct redraw may still
misrepresent the evidence.

For a teaching deck, also inspect the learner route where relevant: each required idea has appeared
before it is needed; a transition grows from a prior observation or task; a visual shows the comparison,
mechanism, or evidence claimed for it; and title, labels, or annotations do not answer a pending
prediction too early. Check that prompts sit where they remain visible in a classroom, labels point to
their referents, full-size evidence is readable on the intended canvas, and hierarchy supports viewing
from a projector. For a continuing lecture, check that its opening retrieves the essential preceding
learning needed now and bridges to the new work without reteaching the whole session or revealing a
pending answer. Confirm that a return to a case advances understanding or a decision, and that the deck
leaves a usable transfer or next step when one is part of the brief.

For each protected teaching function affected by a revision, inspect the changed page, its prerequisites,
and its later use. Check that a new layout, crop, source, or activity has not removed required evidence,
an answer check, a linked note, a timing cue, or a related source record. Apply the same review to
recurring components only where the change can affect them. This is a regression check on teaching
function, not a requirement to re-audit every page after a narrow edit.

Audit reveal timing concretely: a comparison question must show the observation needed to answer it
(do not ask learners to vote between blank A/B displays); a prediction must target information still
unrevealed at that point (do not predict B--D after their results are visible). For a task that asks students
to find or construct an answer, keep the completed answer for feedback unless a worked example is the
intended teaching action; highlighting the target words or showing the finished query can silently
replace the task. An essential action
or error-handling instruction must be in the upper safe viewing area, not only a lower band.

An explicit missing-asset placeholder is a useful draft signal, not a finished classroom material.
Distinguish technical/static and rendered visual checks from classroom projection, live demonstration,
and video-playback checks. Do not claim unperformed live checks. If video is used, keep it as a separate
local file by default, with its own cover, one observation task, offline still, and useful duration on
canvas. Keep technical file paths and return handling in teacher notes; do not add video merely to
satisfy a template.

Report the artifact path, reference version where one governed the design, source/derivative records,
checks run, and the rendering state. Separate static/package, rendered visual, learner-route, and any
live classroom or playback checks. `PASS` means only the stated checks completed on the stated artifact;
a time estimate or synchronized speaker notes are not evidence of a trial teaching run. If rendering is
unavailable or fails, say `draft — rendering unverified`, preserve the PPTX, and state the command/error
summary without claiming a pass.
