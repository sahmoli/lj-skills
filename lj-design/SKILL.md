# lj-design

Develop the selected research focus into a minimum-sufficient discriminating study. State the estimand and repeating units, competing predictions (`H` vs strongest `H_alt`), falsifier, decisive contrast or control, material confounders, and evidenced feasibility. Every design must name an observation on which serious alternatives diverge. Inherit established domain taxonomies, intervention/outcome classifications, and construct names with citation before proposing any split or extension — never coin bespoke labels or ad-hoc typologies where community standards exist.

Read [design guidance](references/design-engine.md) when choosing among experimental/quasi-experimental designs, checking unit mismatches, or specifying an analysis class. Validate saved schema-based design artifacts with [validate_output.py](scripts/validate_output.py). If the supplied hypothesis is not yet testable, restate it into a testable form or name the missing evidence. Question selection belongs to `lj-question`.

When used inside an early-stage project workflow ([Workflow 01](../workflows/01-idea-pilot-proposal.md)), define a **30-minute feasibility probe and predeclared stop/pivot criterion** before committing to a full proposal. A design request alone does not authorize full model runs, simulations, or freezing a pre-analysis plan unless included in scope. Do not invent sample size, statistical power, permits, data fields, or access.

Follow the [suite honesty and authorization rules](../_shared/honesty-constitution.md) and [unified Markdown note contract](../_shared/note-output.md). Explicit output paths and read-only/no-save instructions take precedence.
