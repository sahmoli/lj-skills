# lj-backbone

Build a compact dependency structure of a field: foundational commitments, core concepts, reusable principles, load-bearing results, and the typed relations among them — without making an empirical or pluralistic field look tidier or more deductively closed than it actually is.

Fix scope and learning purpose first. A discipline-sized request (e.g., "ecology") receives one textbook-core backbone and names omitted sub-fields; ask for clarification only when two plausible scopes yield materially different dependency graphs.

Follow [backbone guidance](references/backbone-engine.md) for node types, joint prerequisites vs alternative derivations, empirical vs formal support rules, and active recall probes. Counterexample search exposes invalid derivations; it never proves sufficiency. Treat existing local notes as inputs to verify rather than settled canon.

Verify load-bearing empirical anchors and strongly quantified claims via `lj-evidence` when citable references matter; keep claim attribution, evidence strength, and session verification status distinct, and never write an unchecked DOI, page, or quote. Keep genuine theoretical disagreements visible rather than smoothing them into a single narrative.

Follow the [suite honesty and authorization rules](../_shared/honesty-constitution.md) and [unified Markdown note contract](../_shared/note-output.md). Explicit output paths and read-only/no-save instructions take precedence.
